## 二、实机演示 3 个高光操作脚本（2 分钟稳赢）

1. **演示一：协会管理状态流转（35 秒）**
   - 进入「协会管理 → 周期考核」，展示竞赛会员与非竞赛会员的**差异化考核字段（BR-002）**；
   - 给一名正常状态会员录入一次考核不合格，界面立刻提示状态自动流转为 **「观察状态」**；再演示或查看连续不合格进入 **「待清退」** 流程（**BR-003**）；
   - 点击一名会员的「完整档案」，展示基本信息、任职履历（与会员类别解耦）、考核记录与奖惩汇总。
2. **演示二：题库多对多标签组合检索（35 秒）**
   - 进入「题库管理」，同时勾选算法知识点（如「动态规划」）+ 实现能力标签（如「边界处理」），演示切换 **交集 (AND) / 并集 (OR)** 实时精准筛选（**BR-006**）；
   - 点开一道题查看题面、关联标签与参考题解，快速展示题单与题库统计。
3. **演示三：个人能力评估六维雷达图与薄弱项闭环（40 秒）**
   - 进入「个人能力评估」，切换一名有多次评估历史的竞赛会员；
   - 展示 **SVG 六维雷达图**（当前评估 vs 上期历史评估双层叠加，清晰看到薄弱项提升轨迹）；
   - 指向右侧自动诊断的 **薄弱项清单（< 70 分维度）** 及系统自动关联推荐的 **补强题单**，呼应需求文档的「能力评估 → 训练规划」闭环！
   - 顺手展示 `http://127.0.0.1:8000/docs`（FastAPI 自动生成的 Swagger 文档），印证前后端分离与接口规范。

## 三、老师/同学高频追问 Q&A 预案

1. **问：你们说采用了 SDD（规范驱动开发），和直接让 AI 写代码具体区别在哪？**
   - **答**：直接让 AI 写代码很容易产生概念混淆。比如我们需求里明确区分「备选会员 vs 观察状态」「职务 vs 会员方向」「会员考核 vs 个人能力评估」。我们先在 `.spec/rules.spec.md` 和 `docs/04-数据库设计规范.md` 把这些边界写成硬规则和表结构，再按模块让 AI 实现，最后用 `pytest` 对照 `BR-001 ~ BR-007` 逐条校验，保证代码不偏离需求。
2. **问：为什么选择 Vue 3 + FastAPI + SQLite 这套技术栈？**
   - **答**：Vue 3 组件化清晰、前端交互响应快；FastAPI 基于 Pydantic 强类型校验且自动生成 OpenAPI/Swagger 文档，与我们的 SDD 接口契约高度契合；SQLite 单文件零运维，支持完整外键与多对多关系表，非常适合中期快速迭代与课堂演示，后续需要高并发时依靠 SQLAlchemy ORM 可平滑迁移至 MySQL/PostgreSQL。
3. **问：题库里「一道题涉及多个知识点」在数据库里是怎么落地的？**
   - **答**：我们把题目表 `problems` 和标签表 `tags`（区分算法知识点和实现能力标签）通过中间表 `problem_tag_rel(problem_id, tag_id)` 建立多对多关系，同时把综合难度 `difficulty` 独立成字段。检索时支持 SQL 分组聚合实现多标签交集（AND）和并集（OR）组合查询。
4. **问：个人能力评估和会员考核有什么区别？会不会重复？**
   - **答**：两者目标完全不同。会员考核用于管理资格状态（正常/观察/清退/评优），面向全体正式会员；个人能力评估仅面向竞赛会员，从编程基础、基础算法、模拟逻辑、边界处理、知识点组合、代码调试六个维度生成能力画像、识别薄弱项并推荐补强题单，是后续训练模块的直接输入。
5. **问：如果 AI 生成的代码把原有功能改坏了怎么办？**
   - **答**：我们结合了三道防线：① Git 功能分支隔离（`feature/*`），每次小功能提交一次，出问题可立即 `git diff` 对比或 `git revert` 回退；② FastAPI + pytest 自动化回归测试，合入 `develop` 前先跑全套业务规则用例；③ 人工核对 `.spec/` 契约。

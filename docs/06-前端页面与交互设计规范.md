# 前端页面与交互设计规范（Vue 3 + Vite）

## 一、设计原则与视觉体系
1. **清晰模块化导航**：采用「左侧固定导航栏 + 顶部上下文栏 + 主工作区卡片」经典后台布局，减少对复杂业务步骤的记忆负担（对应非功能需求 `9.1 易用性`）。
2. **语义化状态色彩体系**：
   - 科技靛蓝（`#2563EB`）：主操作、竞赛方向与导航高亮
   - 翡翠绿（`#10B981`）：正常状态、考核通过、转正成功、已完成模块
   - 琥珀橙（`#F59E0B`）：备选会员阶段、观察状态、待审核、候补、薄弱项提醒
   - 警示红（`#EF4444`）：待清退、已清退、考核不合格、缺勤、放弃参赛
   - 静谧灰（`#64748B`）：已退出、归档状态、已报名
   - 淡紫（`#7C3AED`）：能力评估、能力互补组队、暑假集训
3. **响应式与轻量化**：优先适配桌面端（1280px~1920px）实验室大屏及笔记本演示，同时兼顾窄屏折叠布局（对应 `9.6 兼容性`）。图表一律采用原生 SVG，无第三方重型图表依赖。

## 三、关键交互组件规范

### 3.1 六维能力雷达图（`AbilityRadarChart.vue`）
- 纯原生 SVG 实现，无第三方重型图表依赖，支持动态渲染 6 个维度轴线与刻度网格（20/40/60/80/100）。
- 支持同时绘制两条多边形曲线：
  - **蓝色实线填充**：最新一期评估得分
  - **灰色/绿色虚线**：上一期历史评估得分（直观体现训练前后能力提升）
- 低于 70 分的维度顶点高亮为橙/红色警示点，与右侧「薄弱项清单」视觉联动。
- **复用场景**：队伍档案详情中的「队员能力互补对比卡片」直接复用该组件，逐成员渲染六维能力雷达图，配合薄弱项徽章呈现互补关系（BR-005）。

### 3.2 多标签组合筛选器（题库页）
- 明确区分「算法知识点（蓝徽章）」与「实现能力标签（紫徽章）」。
- 支持点击多个标签即时筛选，并可一键切换 `交集 (AND：同时满足所选标签)` 与 `并集 (OR：包含任意标签)`，直接展示 `BR-006` 多对多建模威力。

### 3.3 状态流转防误操作反馈
- 录入周期考核不合格时，前端即时弹出明确提示反馈后端状态机流转结果（例如：「考核已录入，会员张伟已自动流转至【观察状态】」或「连续 2 次不合格，已触发【待清退】流程」）。

### 3.4 训练打卡与考勤组件（`TrainingView.vue`）
- 周任务列表内嵌「补题进度条」（已补题数 / 题单总数），并配「打卡 / 记录考勤」按钮。
- 考勤三态语义化：`PRESENT`（正常，绿）、`LATE`（迟到，橙）、`ABSENT`（缺勤，红）。
- 个人补强计划卡片明确展示 `source_assessment_id` 能力评估快照与关联题单，体现 **BR-007** 训练规划以能力评估为主要输入、历史可回溯。

### 3.5 校赛晋级 / 候补递补流转组件（`ContestView.vue`）
- 校赛采用**个人选手制**（关联 `member_id`），选手状态机：`REGISTERED`（已报名）→ `WAITLISTED`（候补）→ `PROMOTED`（晋级决赛）→ `CONFIRMED`（已确认参赛）/ `ABANDONED`（已放弃）。
- 「晋级决赛」选手提供「确认晋级参赛」与「放弃（触发候补递补）」两个操作；放弃或逾期时后端在同一事务内按 `prelim_rank` 升序自动递补候补首位选手（**BR-009**），前端即时提示递补结果。
- 该状态流转**严禁**自动联动会员管理状态（BR-009 与 BR-003 正交）。

### 3.6 线上初赛异常行为人工复核组件（`ContestView.vue`）
- 异常行为仅「留存证据链接 + 描述」，状态固定为 `PENDING_REVIEW`，原始材料不可覆盖或删除。
- 人工复核以独立弹窗写入复核人与三值结论：`CONFIRMED_VIOLATION`（确认违规）/ `EXONERATED`（排除嫌疑）/ `NEED_MORE_EVIDENCE`（证据不足，需补充），**禁止系统自动判作弊**（**BR-010**）。

### 3.7 能力互补候选组队组件（`ContestView.vue`）
- 点击「生成能力互补候选组合」调用 `/contest/teams/recommend`，基于竞赛会员最新六维能力画像生成互补候选队伍，逐成员展示综合分与薄弱项徽章，并给出互补度评分与建议。
- 队伍档案详情展示「队员能力互补对比卡片」与「成员调整流水（Append-Only）」，保证队员离队后不覆盖历史队伍赛事成绩（**BR-008**）。

## 四、前后端数据契约（前端消费约定）

> 前端禁止硬编码模拟业务数据（G-06），统一经 `frontend/src/api/client.js` 访问 `/api/v1` 后端；以下字段名与 `.spec/api.spec.yaml` 契约一致，后端合入时须对齐。

1. **训练域**（`/training/*`）
   - `TrainingPlan`：`id / name / plan_type(OVERALL|PERSONAL) / member_id / member_name / cycle / source_assessment_id / problem_list_id / problem_list_title / target_dimension / status / description / start_date / end_date`。
   - `TrainingTask`：`id / plan_id / plan_name / title / week / problem_list_id / problem_list_title / member_id / member_name / status(PENDING|IN_PROGRESS|DONE) / attendance(PRESENT|LATE|ABSENT) / solved_count / total_count / deadline / remark`。
   - `TrainingCamp`：`id / name / camp_type(WINTER|SUMMER) / term / team_id / team_name / location / start_date / end_date / status / summary`。
2. **竞赛域**（`/contest/*`）
   - `Team`：`id / name / season / status / leader_member_id / members[] / adjust_logs[]`，其中成员快照含 6 维能力字段 `lang_basic / basic_algo / simulation_logic / boundary_handling / knowledge_combo / coding_debug` 与 `weak_points[]`。
   - `SchoolContestEntry`：`id / contest_id / member_id / member_name / student_no / prelim_rank / prelim_score / status(REGISTERED|WAITLISTED|PROMOTED|CONFIRMED|ABANDONED) / auto / confirm_time`。
   - `Anomaly`：`id / contest_id / member_name / evidence_url / description / status(PENDING_REVIEW) / review_conclusion / reviewer / review_time`。
   - `XcpcResult`：`id / name / round / team_id / team_name / rank / solved / penalty / site / award`。
   - `NonXcpcResult`：`id / name / category / member_id / member_name / award / award_level`。
